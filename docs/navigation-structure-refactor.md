# 二级页面导航结构重构：从「同级页签」到「层级路由」

> 适用范围：控制台原型 `docs/prototype/console.html` 的专家工作室、规则库、知识库三个区域。
> 目标：业务功能与页面内容一字不改，只改「怎么到达」和「到达后停在哪」。
> 判据（沿用 IA 评审已确立的那一条）：**这是目的地，还是某个对象内部的一个面？**
> 状态：**三个区域已全部落地**，`verify-console.js` 484 项行为契约全绿；另做过一轮真实浏览器
> 逐状态截图核验并修掉 3 个 jsdom 看不见的缺陷（见文末「真实浏览器核验」）。

## 一、问题清单

### 1.1 交互层：同级页签带来的七个具体问题

| # | 现象 | 成因 | 后果 |
|---|---|---|---|
| P1 | 刷新后回到起点 | 页签只是 DOM 显隐，"选中的是哪一个 + 现在停在哪一页"只活在内存变量里 | 刷新、重启、把链接发给同事，一律回到集合页第一个页签 |
| P2 | 深层入口无法直达 | 位置没有可书写的地址 | 想让人看"某个规则包的试算"，只能口头描述"规则库 → 找到 XX 包 → 点试算" |
| P3 | 浏览器前进/后退异常 | 切页签不产生历史条目 | 按返回键要么直接离开整个区域，要么毫无反应；用户"退回上一页签"的预期得不到响应 |
| P4 | 页签选中态与实际内容不一致 | "选中的页签"和"显示的内容"是两份状态：一个由点击处理函数改，一个由渲染函数改 | 只要出现任何没走处理函数的路径（深链、默认选中、重绘），两者就对不上 |
| P5 | 进入动作悄悄重置当前对象 | `setView` 里做默认选中 | 任何进入该区域的动作（含深链）都把已选条目换回第一个，条目页上没保存的草稿随之丢失 |
| P6 | 集合级工作面被绑在条目上 | 事实词表、跨库检索这类"属于整个区域"的面，与条目内部的面混在同一行页签 | 没选中任何条目时，这两个面无法访问——它们本来就不依赖某个条目 |
| P7 | 动作结果看不见 / 被清掉 | 反馈写在即将被切走的那一页上，且写入早于跳转 | 用户看不到"保存成功"；或刚写完就被路由清空 |

**P4 的真实根因（值得单独记一笔）**：我们把"检查器正在讲谁"和"这一页正在显示哪个条目"写成了同一个 CSS 类。前者每次换页换面都该清空，后者必须由状态渲染出来。混用的表现是——重绘刚刚写好的高亮，会被下一次换页立刻擦掉，于是"检查器说看的是 A，列表里却没有一行是亮的"。

### 1.2 呈现层：层级被压平

| # | 现象 | 为什么不合理 |
|---|---|---|
| V1 | 一行页签读作「专家工作室 / 专家 / 流程 / 清单 / 授权」 | 实际是四层关系：区域 → 集合 → 条目 → 条目的一个面。五个并列按钮把四层压成一层 |
| V2 | 集合页（清单）与条目页（流程/清单/授权）共享同一行 | "我还没选专家"和"我在看这个专家"变成同一行的两个按钮，两种完全不同的处境被画成同级 |
| V3 | 条目标题埋在卡片内（`<h2>`） | 进入条目页后，页面主位仍是区域标题，用户不知道自己"在哪个对象里" |
| V4 | 条目内部子导航与区域级页签视觉权重相同 | 层级差读不出来，只能靠文字猜 |

### 1.3 根因一句话

**用"并列切换"的控件去表达"父子包含"的关系。** 页签是为"并列目的地"设计的；而"集合 → 集合里的一个条目 → 条目内部的一个面"是包含关系。只要关系被画错，上面这些症状就会各自在不同入口复现——它们不是十一个独立 bug，是同一个错误的十一种表现。

## 二、改造方案

### 2.1 页面类型三分

| 类型 | 是什么 | 例子 | 是否有子导航 |
|---|---|---|---|
| 集合页 | 这个区域有什么 | 专家清单、规则包清单、知识库清单 | 无（它就是这一区的落地页） |
| 条目页 | 集合里的一个条目 | 单个专家、单个规则包、单个知识库 | 有（条目内部的面） |
| 集合级模式页 | 属于整个区域、不依附某个条目的工作面 | 事实词表、跨库检索 | 无 |

### 2.2 路由结构

```
#<area>                        集合页
#<area>/<itemId>               条目页（面由进入场景决定）
#<area>/<itemId>/<face>        条目页的某个面
#<area>/<itemId>/<face>/<sub>  面里的具体对象（如某一篇文档）
#<area>/<mode>                 集合级模式页
```

| 区域 | 集合页 | 条目页的面 | 集合级模式 |
|---|---|---|---|
| 专家工作室 | 专家清单 | 流程 / 清单 / 授权 | — |
| 规则库 | 规则包清单 | 规则 / 试算 | 事实词表 |
| 知识库 | 知识库清单 | 文档 | 跨库检索 |

### 2.3 三条硬约束（URL 是唯一真源）

1. **只有 `go()` 写 URL，`applyRoute()` 只读取 URL 并渲染**，绝不回头改它。于是"选中的页签"与"显示的内容"不可能对不上——它们是同一 URL 的两次读取。
2. **`go()` 先写 URL、再立刻渲染**，不等 `hashchange`。`hashchange` 是异步的，只依赖它会让点击后有一拍"页签已换、内容未换"的窗口；用 `appliedRoute` 让随后到达的 `hashchange` 认出"已渲染过"，不重复渲染。
3. **地址指向不存在的对象时，落到集合页并说明原因**，不静默、不残留旧内容。

### 2.4 导航控件各归其位

| 层级 | 控件 | 位置 |
|---|---|---|
| 区域 | 左侧菜单 | 常驻 |
| 条目 | 面包屑（`← 区域 / 当前面`）+ 条目标题（`<h1>`） | 条目页顶部，占这一层主位 |
| 条目内部的面 | 子导航（`.subtabs.nested`） | 条目标题正下方，视觉权重低于区域级页签 |
| 集合级模式 | 无子导航 | 与集合页同级，从区域入口直达 |

### 2.5 进入场景决定默认面（landing）

同一个条目，从不同场景进去默认停的面不同：

- 点列表里**已登记**的专家 → **流程**（那是它的本体，看它干什么）；
- **新建 / 复制**出来的专家 → **清单**（身份还没定下来，先定标识与名称）；
- 调用方显式指定（如从试算跳过来）→ 以指定为准。

行尾写出去向（「→ 流程」），标签与真实落点来自**同一个判断函数**，不允许各写一份——否则又变成两份状态。

### 2.6 状态管理调整

| 项目 | 改动前 | 改动后 | 为什么 |
|---|---|---|---|
| 当前面 | `expertSubview` / `ruleSubview` / `kbSubview` 三个变量 | 删除，一律读 URL | 平行状态迟早与 URL 不一致（P4） |
| 选中语义 | `.sel` 一个类同时表示两种含义 | `.sel`（检查器在讲谁）+ `.sel-row`（这一页在显示哪个条目） | 混用会互相擦除（P4 根因） |
| 进入区域时的选中 | `setView` 里做默认选中 | **首次进入不替操作者选第一条**，检查器先解释当前页面；选中只由点击产生，回集合页沿用 | 进入动作不许悄悄重置当前对象（P5）；页面级说明比「替你选一个」更能讲清这一页 |
| 动作后的反馈 | 先写消息、再跳转 | **先跳转、再写消息**，且写在跳过去之后看得见的位置 | 路由会清空集合页消息；写在原页面等于没写（P7） |
| 未保存草稿守卫 | 换页就拦 | 只在"真的要换掉草稿"时拦（切条目；切区域 / 切面 / 回清单不动草稿） | 过度拦截比不拦更烦人 |
| 守卫时机 | 先改数据再弹窗 | **先弹窗、确认后才改数据** | 否则用户点"取消"时新条目已经躺在列表里 |

### 2.7 跳转关系

| 从 | 动作 | 到 |
|---|---|---|
| 区域菜单 | 点击 | `#<area>`（集合页，沿用上次选中） |
| 集合页列表行 | 点击 | `#<area>/<itemId>`（面由 landing 决定） |
| 条目页子导航 | 点某个面 | `#<area>/<itemId>/<face>` |
| 条目页面包屑 | 点返回 | `#<area>`（不动草稿，不拦截） |
| 集合页模式入口 | 点击 | `#<area>/<mode>` |
| 知识库检索结果 | 点命中项 | `#knowledge/<baseId>/docs/<docId>`，并在文档页写明"你是从检索结果跳过来的" |
| 新建 / 复制条目 | 提交成功 | `#<area>/<newId>/<配置面>` |
| 删除当前条目 | 确认 | `#<area>`（回到集合页，结果写在集合页） |

## 三、实施步骤

每一步都可独立验收；验收方式是行为级校验脚本（jsdom 驱动真实 DOM 与真实事件），不是肉眼看截图。

### 阶段 1：统一路由内核
- **范围**：新增 `routeKey / readRoute / showRoutePage / applyRoute / go`，替换原先三份各自为政的 hash 同步器（专家、规则、知识各写一份）。
- **受影响模块**：页面切换（`setView`）、检查器（`finishInspector`）、浏览器前进后退（`hashchange`）。
- **验收**：切区域、切页、刷新、深链、前进、后退、指向不存在的对象——七个场景各自有断言。

### 阶段 2：三个区域的标记改层级
- **范围**：专家工作室、规则库、知识库从"N 个同级 `.subview`"改为"集合页 / 条目页 / 模式页"三层容器；条目页加面包屑与 `<h1>` 条目标题；条目子导航改 `.nested` 并从里面去掉集合本身那一项。
- **受影响模块**：三个区域的全部卡片（内容不变，只换容器）、样式（新增 `.crumb / .item-head / .item-title / .subtabs.nested`）。
- **风险**：容器嵌套层级变化容易留下冗余包裹层，被 `.subview{display:none}` 藏起来后页面整块空白——每改一个区域立即渲染一次确认。

### 阶段 3：点击与落点改导航
- **范围**：列表行点击、子导航点击、文档行点击全部改为写 URL；`DEFAULT_PICK` 改为"只选中、不切页签"。
- **受影响模块**：`openExpert / openRulePack / openKnowledgeBase`、`selectDocument`、能力节点与文档行的行内 `onclick`。
- **验收**：点一行一步进入条目页；任一时刻只有一个面可见；换面不丢"现在看的是谁"。

### 阶段 4：进入场景与落点提示
- **范围**：新增 landing 判断（已登记 → 本体面；新建/复制 → 配置面）、行尾去向标签。
- **受影响模块**：`renderExperts` 行渲染、`newExpert / copyExpert`。
- **验收**：标签文案与真实落点同源——断言"行尾写的去向 = 点进去停的面"。

### 阶段 5：状态与时序收敛
- **范围**：删除三处影子状态；`.sel` 与 `.sel-row` 分离；集合页不重置选中；统一"先跳转、再写消息"；未保存草稿守卫（含时机修正）。
- **受影响模块**：`markSelected`、三个列表渲染、DAG 节点、文档行、资料行、消息写入点。
- **风险**：两类选中若再次混用，表现是"检查器说看的是 A，列表里却没有一行是亮的"——这是本项目已踩过一次的坑，改动后用断言钉住。

### 阶段 6：回归与核验
- **范围**：行为级校验全量通过；真实浏览器（无头 Chrome）截图核验集合页 / 条目页 / 面包屑 / 子导航 / 模式页 / 守卫模态。
- **验收**：校验条目数只增不减，且每一条都对应一个真实场景而非文案匹配。

## 附：如何判断某个未来新增的面该放哪一层

1. 它是否需要先选定一个条目才有意义？→ 需要：条目页的一个面；不需要：集合级模式页。
2. 它是一次动作还是可以停留的目的地？→ 动作（新建、重命名、改一条规则）：抽屉或模态，不占一层导航；目的地：占一层。
3. 它会不会让人想"把这个链接发给同事"？→ 会：必须能写成 URL。

### 知识库

检索命中跳转后，提示写在跳过去之后看得见的地方。

### 抽屉与模态（三个区域共用）
- **抽屉**：新建 / 编辑 / 新增文档。列表留在原位，动作不搬走上下文；有未保存改动时关闭先问一次
  （继续编辑 / 丢弃并关闭），不用系统 `confirm`。
- **模态**：删除。写明影响面；被后端拒绝时确认按钮**不可用但仍在**，原因写在 `#modalBlocked`
  里并点名专家与状态码（409）。

### 过程中修掉的真实缺陷
1. `closeMenus()` 把所有 `[aria-expanded]` 一并重置成 false，把「检查器」开关这类非菜单的展开控件
   一起压掉——点开关抽屉开了，无障碍状态却说没开。已收窄到 `[aria-haspopup="true"]`。
2. 模态的「具名入口」路径只挂了 onclick、没有关闭对话框，点确认后模态不消失。
3. `setView()` 结束时会在检查器里填一段占位文案，导致「为空才回指当前条目」的补写判断永远不成立——
   换面后检查器掉回页面级说明。已改为无条件回指。
4. 工具变成对象后，能力标识被拼成 `mcp.files.[object Object]`。
5. 从别的页改了 MCP 服务器状态再回专家「清单」面，授权区仍显示已不可授权的工具（进条目页时不重读）。

## 真实浏览器核验（2026-10-12 补做）

jsdom 只能断言行为，验不了排版。所以另开一轮无头 Chrome（CDP）逐状态截图，覆盖
集合页 / 条目页 / 面包屑 / 子导航 / 模式页 / 抽屉 / 未保存守卫 / 删除模态 / 窄屏共 15 个状态，
再看裁剪放大图与 DOM 探针把「看着可疑」落成事实。**截图核验抓到了 3 个 jsdom 结构断言看不见的缺陷**：

1. **`hidden` 属性被作者样式压过，「有未保存的修改」从抽屉一打开就常亮。**
   成因：UA 的 `[hidden]{display:none}` 是权重最低的一条，而 `.chip` 声明了 `display:flex`，
   于是 `#dirtyTag.hidden === true` 成立、`getComputedStyle` 却给出 `display:flex`，
   实测盒子 79×42 画在抽屉右上角。最难查的一点是**三个信号都说它藏起来了**：DOM 属性、
   断言、读屏软件。修法是在样式层加一条 `[hidden] { display: none !important }` 兜底，
   而不是逐个改成类控制——任何将来声明了 `display` 的类都不该能复活一个被显式隐藏的元素。
2. **状态写出来了却看不见：`.doc-row.sel-row` 没有任何视觉差异。**
   文档行的渲染写的是 `sel-row`，样式层里写的却是 `.doc-row.sel`，两边对不上。
   于「当前预览的是哪一篇」在列表里毫无线索——检查器和预览都跟着 `selectedDocId` 走，
   只有列表不跟。已改成与 `.list-item.sel-row` 同源（边框 + 底色 + 左侧 3px 强调条）。
3. **模式页没有回头路。** 左侧导航点「知识库 / 规则库」走的是 `DEFAULT_PICK`，落到**第一个条目**，
   不是集合页；模式页原本连面包屑都没有，进来之后只剩浏览器后退。
   已给两个模式页补上 `← 规则库 / 事实与运算符词表` 的面包屑，并去掉那处用来补空白的 `margin-top:16px`。

另外顺手改掉一处**文案承诺了页面做不到的事**：检索命中写的是「点击可在右侧打开全文」，
而 `openSearchHit()` 实际是 `go()` 跳到那台库的文档页（右侧那时显示的是模式页说明卡）。
已改成「点击跳到该知识库的文档页打开全文」。

### 核验过、确认没问题的几点

- **删除模态的遮罩覆盖检查器**：`elementFromPoint(检查器中心)` 返回 `DIALOG#modal`，点击被正确截住。
- **被阻断时确认按钮不可用但仍在**：`#modalOk.disabled === true`、`opacity 0.5`、`#modalBlocked` 可见。
- **集合页 / 条目页 / 模式页三层的地址与画面一一对应**，15 个状态的 `location.hash` 全部落在预期层级。
- 规则库条目页的「内置只读」只出现一次状态芯片（副标题里的同名字样是描述，不是重复芯片）。

### 新加的 8 条契约（`verify-console.js`，484 项全绿）

这 8 条都写成**结构性**的，因此在 jsdom 里也守得住——它们约束的是「样式层有没有跟上状态层」，
而不是像素。已用修复前的版本反测：**其中 6 条转红**，说明它们真的能抓住刚修掉的缺陷，不是空转。
