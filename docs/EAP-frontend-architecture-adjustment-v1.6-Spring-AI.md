### 0A.1 保留架构与当前模块归属

- 保留 Java 25 / Spring Boot 4.1.1 / Spring AI 2.0.2、Maven reactor，以及 Vue 3 + TypeScript + Vite+ + pnpm workspace + Tailwind 4 / 标准CSS变量；不引入Sass或另建React Renderer。
- 后端保持单一Java服务：`backend/eap-api`为稳定能力契约；`eap-engine`为确定性执行、任务/Run及持久化；`eap-ai`为模型/Chat/Skill及交付整合；`eap-web`为HTTP边界；`eap-runtime`只保留启动装配、运行资源和跨模块测试。依赖方向 runtime→web→ai→engine→api；普通DTO在application.dto，AI响应在ai.dto。已应用迁移不重写，不为拆模块改变API/权限。
- 共享UI、hooks/effects/layout/plugin等落点以[唯一共享模块规范](decisions/frontend-ui-shared-module-boundaries.md)为准；组件以`frontend/packages/ui/src/index.ts`实际导出为准。允许实现用户明确需要的跨仓库基础定义，不因没有第二消费者阻止，但必须有实现/公开入口/样式/验证，不能建空壳。
- `@eap/ui`为组件与统一`Icon`/类型化name入口，`@eap/icons`仅内部本地Lucide资源层；Reka为内部交互依赖。已按需纳入shadcn TooltipContent并保留来源/许可，不等于全库迁移；页面不另设第三方UI入口。`@eap/style`不持有路由/存储，应用负责偏好持久化。
- Vue Router、Pinia、Query、Monaco、xterm、Vue Flow及SDK拆包属于按缺口评估的演进选项，不是本轮无条件安装/迁移指令；先复用现有runtime-client、composable、受信Host和领域页面。新文案走i18n，不按旧建议目录一次性搬迁。
- 前端测试统一在所属应用/包根`__tests__/`，与`src/`同级；测试夹具、快照与类型合同一并隔离，见[测试目录决策](decisions/frontend-test-layout.md)。工程检查集中在`scripts/vsh`工作区包；跨包只允许声明依赖及公开exports，禁止私有源码直引/别名绕过，包含运行时文件环和工作区声明环门禁。审查反例修复及用户批准模板语法修复后，最新104文件601项、根check、类型/架构/测试lint-fmt/build通过；glob展开限定复核与业务验收分开，见[工具决定](decisions/frontend-tooling-boundaries.md)。

### 0A.2 责任边界（规范性决定）

```text
Chat / SQL Expert / 后续 Mission / Builder AI 辅助
                   |
                   v
          EAP AI Application Service
                   |
          Spring AI 2.0.2
      ChatClient / ChatModel / Tool Calling / ChatMemory
          |                     |
   官方模型 Starter          EAP 受控 ToolCallback
   (按需扩展供应商)            -> Capability/Policy/Executor
                                 -> Trace / Artifact

外部编码 Agent：CodexAdapter / 后续官方协议适配器
    -> 独立会话、审批、执行与证据；不伪装成普通 ChatModel

Mission/Run/Approval/Verification：EAP 领域层，不能由 ChatMemory 替代
Workspace Plugin：Vue UI 扩展层，不等于 Spring AI Tool / MCP / Skill
```

**原则**：Spring AI 负责通用模型接入、消息、Advisor、工具调用编排及可选记忆/MCP 客户端集成；EAP 负责工具权限、确定性工程能力、任务状态、审批、执行证据、持久化和独立验证。Spring AI 的 MCP 支持并不意味着现有 EAP MCP 登记服务已经完成真实协议接线，必须核对当前实现与授权桥接后再宣称可用。不得同时维护第二套模型 Provider 注册与调用循环；确有业务兼容需求时允许保留薄适配桥。

### 0A.3 模型、配置与执行的有效合同

- 模型状态至少区分`disabled / not_configured / configured_unverified / available / error`；只有真实验证才显示available，配置存在不等于连接成功，不自动计费探测。Fake ChatModel验证普通对话/工具/拒绝/错误/SQL回退，不替代供应商能力验收。
- 用户可在本地设置配置、启停和切换连接/外部Agent；Spring AI官方集成和程序化构建承载模型协议，旧环境属性不是唯一产品事实源。迁移见[环境说明](environment.md)。凭据由本地服务保护，不进入浏览器、Trace或Artifact；浏览器不直连供应商。
- Chat复用`EngineeringChatService`与受控API，显示所选模型、真实/模拟与工具授权结果；多供应商按需接官方Starter，OpenAI-compatible不保证所有供应商语义。Codex/Hermes有独立入口与配置，不走普通ChatModel，不套用SQL缓存/压缩。
- 普通API连接显式选择`chat-completions / responses`，不由域名猜测；旧数据默认前者。Responses复用官方SDK与Spring AI记忆/调用边界，首片仅文本/代码提案、不支持Git工具；协议变更提升revision并须重新确认会话，禁止自动降级重试或迁移凭据。账号认证与wire协议分开，实网恢复仍待用户验收。
- 模型只提出工具请求，EAP负责权限、路径、参数、执行和证据；保持工具调用上限。内存ChatMemory不是持久会话、任务审计或可恢复Mission；SQL规则、缓存与失败回退保留，规则输出不能标成模型分析。
- 已有CLI直接复用Capability / Handler / ProcessExecutor；命令模板属于能力，进程生命周期属于执行器，Task/Mission只关联和投影。Chat/Expert/看板不为同一Git操作另拼命令或另建执行器；参数数组、超时、限额、环境策略、脱敏及真实进程回归须保留。
- Java默认是**本机本地服务**，UI与执行共置；可保存本机连接及工作区绑定。UI标签/intendedPath不是写权限，不静默扩到父目录/整盘；不做远端多租户实例代持异机路径/密钥或隔离云VM。Python只作安装引导，不作Agent宿主。见[运行环境](running-context.md)。
- MCP是互操作协议，不是本地CLI必选包装，也不提供目录授权/进程恢复。复用Spring AI MCP集成并对接EAP授权，只有真实`initialize → tools/list → tools/call`及拒绝/超时/隔离证据才能称接通；登记、探测或Fake Handler不算。stdio与远端HTTP安全策略独立，工具标识保留服务器命名空间。
- Skill、Knowledge、Expert/DAG、Workspace Plugin与Capability保持各自生命周期；Skill指导不授予执行权限，知识检索必须受授权范围限制。知识更新/删除一致性与引用溯源须验证，是否引入向量检索由评测决定。现有DAG不是永久专家产品定义，也不等于自主Agent。
- 优先通过受支持CLI/SDK/协议复用已有Agent Harness，只补证明存在的缺口，不重造模型工具循环。记录持久化不等于进程恢复；证据不足记UNKNOWN并阻塞下一次启动，不能用父进程消失/缺PID证明进程树结束。取消、人工核对和跨重启接管仍按实际能力单独验收。
- 用户主路径是输入需求、引用文件、选专家及模型/Agent、强度与审批、受控执行并审阅；普通仓库需求无需先做Builder/Handoff/完整Mission。无模型时确定性能力和手工设计仍可用，优先真实自身页面交付，不连续扩建连接管理。
- 插件只贡献受信内部工作面，不改变五入口；Manifest不能任意import路径/URL、修改全局容器或自动授予权限。停用/卸载与数据删除分开，保留任务/版本/审计。第三方可执行UI须独立隔离/来源/兼容/许可评估，未完成前不开放。
- Electron共享Vue UI；`nodeIntegration:false`、`contextIsolation:true`、`sandbox:true`、webSecurity开启。preload只暴露具名方法，不暴露通用IPC、任意文件访问/shell；Main验证路径/参数/权限。Web缺能力返回unsupported；安装、签名和各目标OS须真实验证，脚手架不等于桌面产品交付。

更多执行边界见[工具接入决定](decisions/tool-integration-runtime-boundaries.md)、[扩展边界](decisions/extension-boundaries.md)、[桌面规范](desktop-spec.md)。旧S0–S3、CLI/扩展静态审计及详细设计只在[历史§0A](records/product-plan-history.md#section-0a)和[历史§2C](records/product-plan-history.md#section-2c)保留，不作重复实施指令。

### 0A.4 Agent能力与本地运行环境演进

规范细节与源码依据见[技术路线回顾决定](decisions/agent-runtime-evolution.md)。当前继续Spring AI，LangChain4j仅在明确自主协作需求或可复现框架阻碍后做同条件对照；记忆/RAG/MCP的应用缺口不证明框架不支持。不长期并存两套模型工具循环。

- 对话历史、模型窗口、任务工作记忆、长期记忆与本轮检索材料分开。现有知识/Skill逐轮清空保护保留，替代方案须处理派生回答/摘要的撤权与版本失效；不只增加持久Store就宣称可恢复。
- 上下文在现有拼装路径统一预算、来源、相关性选择、输出预留与可解释限额；检索先建立真实问题/预期来源基线，再决定向量、混合检索或重排。字符上限不是token用量。
- MCP首片是一个只读服务器的真实Client闭环；A2A面向独立Agent协作，内部DAG不必套协议。Server、A2A与自主多Agent按需求另批，不按教材章节全部实现。
- 系统工具引用与EAP受管工具并存，后者锁版本、校验、安装回滚、在途保护；仍复用现有CLI/Capability/Executor。安装需明确动作，不允许模型静默下载或全局安装。
- TD-01分离可信工具定义与本机路径/连接/实例绑定，自动汇总已声明能力、探测已知依赖，未知来源仅候选导入；不扫描整盘或运行未知脚本，主动探测与低副作用检查分开，保留停用/授权及在途快照。TC-01/TC-02明确Java运行时、前端Host交互实例及Electron具名能力；调用入口/Schema/范围/审批、结果与贡献呈现分离，不新增绕过策略的任意执行口。先已有Git真实调用，再人工验证草稿实例；反向Agent调用另评审。细则见[工具发现](decisions/agent-runtime-evolution.md#54-工具发现与本机绑定td-01)及[调用合同](decisions/agent-runtime-evolution.md#55-调用执行归属与呈现tc-01--tc-02)。
- 本机数据根分配置、工具、任务scratch、产物、缓存和日志；先盘点旧相对路径并验证迁移/恢复。资源须有归属、限额/保留期与清理责任，运行中/UNKNOWN不自动回收，用户仓库不随插件或工具卸载删除。

### 0B.3 桌面外壳与五入口的设计合同

Java 是本地服务端实现，不决定页面必须采用网站式导航。当前可继续用 Vue/Vite 浏览器承载验证；未实际由 Electron 宿主承载时，不展示假最小化/最大化/关闭按钮。后续宿主集成复用这套外壳，不重做业务页面。

```text
┌────────────────────── 约 44–48px 顶部上下文栏 ──────────────────────┐
│ EAP / 折叠侧栏   当前项目·会话/任务标题        摘要 终端 变更 源文件 ⋯ │
├──────┬──────────────────┬────────────────────────┬─────────────────┤
│      │ 新对话           │ 当前工作面             │ 可选详情面板    │
│ Code │ 项目 A           │                        │ 当前会话摘要    │
│ Work │   任务看板       │ 对话 / 场景 / 编辑器   │ 授权、步骤      │
│ 场景 │   会话 1         │ / Diff / 设置          │ 变更、来源      │
│ 专家 │ 项目 B           │                        │                 │
│      │ 自由对话         ├────────────────────────┤ 默认关闭        │
│ 设置 │                  │ 输入区 + 底部操作条    │ 独立滚动        │
└──────┴──────────────────┴────────────────────────┴─────────────────┘
 52–64px   约 240–280px        minmax(0, 1fr)          约 300–360px
```

尺寸为 CSS px 的初步建议，不从录屏像素反推硬编码；100%/125% 缩放、1280×800 和 1440×900 为首轮验收视口，窄窗口采用可收起侧栏。不得用全页横向滚动解决输入区溢出。

**唯一工作台与数据来源**：真实服务与mock渲染同一`ChatWorkspace`、`createChatSession`、`TaskComposer`、导航和面板，使用同一`createChatApi`/DTO与`/api`路径。`vp run dev`代理Java；`vp run dev:mock`或`VITE_USE_MOCK=true`仅开发时注册模拟服务，生产不启用。界面不提供来源切换按钮，不另建演示首页；场景、版本和任务回链不改变来源或自动发送。

前端、真实后端与mock按同一合同推进，mock不能永久替代业务实现。真实失败不回退mock，未实现mock端点返回404且不回退Java/模型；模拟结果明确未读写仓库、未跑真实测试。看板/原型版本均共用API与门禁；本机草稿不等于服务端不可变版本。当前模拟服务边界与早期分支纠偏见[历史§0B.3](records/product-plan-history.md#section-0b-3)。

窄窗口另以约 708px 宽的当前问题视口回归：侧栏抽屉需有遮罩、明确关闭入口、Esc/外部点击退出；关闭后正文与整个输入操作条可达。发送、审批和模型选择不得落在不可滚动的裁切区域。冷启动优先进入 Code 任务工作面或恢复用户最后的工作上下文，不因旧 SQL 路由默认值而永久进入分析控制台；SQL 仍作为可选确定性能力保留。

| 区域 | 必须行为 | 当前纠偏 |
|---|---|---|
| 活动栏 | 五入口顺序固定；设置贴底；图标、文字、选中态、键盘焦点明确 | 不继承旧深色后台 `.rail`；不因插件数量增加一级入口 |
| 上下文侧栏 | Code/Work 展示项目、会话、任务入口；场景/专家优先保留来源会话上下文；设置切换成分类栏 | 现有“设置子菜单/SQL入口列表”不能替代项目树；Builder A/B 是实例，不应永久暴露成产品分类 |
| 顶部栏 | 当前会话/任务名称和相关操作；无上下文的动作禁用或隐藏；运行时状态紧凑显示 | 不长期占用空间展示品牌、假工作区切换和全局刷新；本机任务分组不得伪装真实仓库 |
| 工作面 | 高度受窗口约束；正文、列表独立滚动；切换入口保留草稿、选择及滚动位置 | 不将标题、告警、卡片、页脚层层堆叠导致输入框不可见 |
| 会话工具面板 | 摘要、终端、变更、源文件入口在对话顶栏右侧，再点一次关闭。**布局按面板分流，不得统一成同一套展开方式**：① **摘要** 锚定为右侧栏，自动收缩会话区宽度，正文与输入仍可用；② **源文件** 为右侧浮层（可含搜索），目录以**树展开**浏览，不是进入式 ⌂/↑ 换层，也不应用全屏替换对话；③ **终端** 停靠在对话**下方**底栏，收缩会话区高度，**不是**右侧锚定栏；④ **变更** 锚定右侧栏展示候选/已应用/目录原有修改。摘要卡可跳到变更、源文件、终端或输入授权 | 设置页不固定展示 SQL 检查器；终端未接通时可打开底栏诚实空态，不得展示伪日志或授予任意 shell。不把风险条数、增删行数写成没有的数据 |
| 底部 | 聊天输入区固定在工作面底部；系统状态无需重复成全局脚注 | SQL 特有指标只留在分析工作台；非 SQL 页面不显示“确定性覆盖/模型占比”等永久页脚 |

### 0B.4 Code、Work、场景、专家与插件的关系

此前实现把五入口理解为“五组页面导航”，造成主流程断裂。目标关系如下：

| 概念 | 用户含义 | 与现有实现的边界 |
|---|---|---|
| Code / Work | 同一应用的工作模式，共用会话骨架，默认目标与可用场景不同 | 不是两套模型连接、两套会话引擎；Work共用交互骨架，办公执行仍未接入，不能冒充已支持 |
| Project / Repository | 任务所属项目及**本地服务所在机器**上确认的真实目录、仓库和基线（产品默认 UI 与 Java 共置） | 浏览器显示标签不是 repoId；本地服务可绑定本机工作区；禁止远端多租户实例代持异机路径；自由对话可不绑定仓库 |
| Session | 保留用户对话、草稿、选择及关联执行 | 不是 ChatMemory 的别名，也不是一个长期后台进程 |
| Scenario | 适用 Code/Work、指引、资源依赖、默认配置和交互流程的可复用组合 | “原型 → 代码”“代码审阅”“文档编写”可为场景；不是插件本身，也不是一次执行记录 |
| Expert | 配置驱动的专业角色，明确可访问资源与可用能力，可加入任务 | `general/sql/frontend`是内置指导角色；单专家授权知识Chat已接，完整角色/其他资源和DAG执行未因此完成 |
| Workspace Plugin | 提供受信 UI 页面与交互贡献的内部扩展 | Builder 编辑器可由插件提供，场景调用它；插件不自动取得工具权限，不决定活动栏结构 |
| Task / Run | 具体需求及一次尝试的状态、变更、验证、审批与证据 | 会话可关联任务；无需先补完整调度平台才能做一次受控开发 |

**场景最低配置合同（目标字段，非新增表承诺）**：`id / version / name / description / supportedWorkModes / instructions / resourceRefs / requestedCapabilities / defaultSessionMode / defaultApprovalPolicy / outputContract`。资源引用使用现有 Skill/MCP/Expert/Capability 标识；复用既有配置与版本能力，确认存储缺口后再决定结构，不建立平行注册中心。

场景列表先做本地可用、部分缺依赖、禁用三态；详情展示已安装/未安装、已配置/未连接、允许/询问/禁止。全局启用只是可用上限，场景默认选择和会话授权不能绕过它。预设可只读、允许复制为用户配置。市场是后续入口，未实现时隐藏或明确空态，不制作假可安装结果。专家入口优先“可选用/可管理”，无需为匹配录屏先做市场。

**插件化演进**：看板UI与原型设计器可作为可信功能插件；“原型到代码”是引用插件及核心服务的场景，不是单一前端插件。Task/Run、审批、执行、目录和验证不随插件停用而消失。先以现有看板收敛版本/兼容、贡献点、activate/dispose、实例配置和依赖失败合同，再迁设计器；不先建空SDK。启停不等于外部安装，前端安装不自动补齐Java服务。缺依赖显示不可用；激活失败回滚局部贡献；停用释放UI资源、保留任务/版本/产物，在途任务仍由核心观察。任意第三方同页JS不能仅靠Manifest隔离；外部包来源/兼容/升级回滚/隔离另行评审。完整门禁见[插件与场景决定](decisions/agent-runtime-evolution.md#6-核心插件与场景)。

### 0B.5 输入框：相互独立的选择与可见状态

```text
┌──────────────────────────────────────────────────────────────────┐
│ 已引用：App.vue  work-pages.css  原型版本 v3  ×   协作：前端专家 × │
│ 描述需求…… 可粘贴文本；文件/图片支持范围明确                     │
│                                                                  │
│ ＋  智能体⌄  审批策略⌄        上下文状态  模型·连接⌄ 强度⌄  发送↑ │
└──────────────────────────────────────────────────────────────────┘
```

| 选择轴 | 目标行为 | 当前实现与限制 |
|---|---|---|
| 任务目标 | 讨论、审阅、按原型开发等，场景可提供默认值 | 当前 `TaskContext.mode=chat/code` 是输出目标，不是完整执行模式 |
| 会话执行模式 | 聊天不使用工具；规划仅做允许的读取和计划；智能体使用已授权执行器 | 当前无完整规划/Agent 模式；不能只改 select 标签就宣称支持；插件创造可延后 |
| 审批策略 | 与执行模式独立，显示实际生效策略和每次待批准动作 | 当前仅 `review/read_only`；没有风险审核服务时，不得把 `review` 命名为“AI 审核” |
| 模型 | 只选已启用连接上、允许列表中的具体模型；同名模型显示所属连接 | 连接变更或模型失效需明确提示；切换会清服务端记忆时提前说明 |
| 推理强度 | 根据当前模型能力动态显示，提交值来自能力映射 | 不把所有模型统一硬套“最大”；不支持时隐藏或解释禁用，切换模型后重新校验 |
| 专家、指令与引用 | 可添加、可移除、能检查将发送的内容；管理入口返回后不丢上下文 | 固定角色与配置专家应分清；当前文本附件不能承担图片和录屏理解 |
| 上下文状态 | 展示附带资料及限额；有真实 token 统计才显示 token 用量 | 不用装饰性圆环伪装计量；过大资料分块或拒绝，不静默截断 |

`＋` 菜单按文件/原型、指令、专家、技能、MCP 等类别组织，并提供搜索、数量、选中项和管理跳转。未实现能力在交互原型中明确标“演示”，正式界面隐藏或说明不可用；菜单不能成为尚未接通能力的广告墙。弹层定位在输入区附近，空间不足时翻转，Esc/外部点击关闭，选择项不清空正文，焦点回到输入区。

模型连接路径是 **凭据接入 → 获取目录 → 选择允许模型和默认模型 → 会话选择 → 按模型能力选择强度**。ChatGPT 账号登录与 OpenAI API Key 是两个凭据入口；DeepSeek 使用 Key。目录刷新失败时保留上次目录并注明缓存时间、错误和重试；允许列表不能因刷新自动全选；发现模型不等于验证调用成功。模型/Agent 目标也不合并：普通 ChatModel 不自动具备仓库工具循环。

```mermaid
  Configuring --> Draft: 应用配置，不发送
  Draft --> Checking: 用户发送

  Blocked --> Draft: 定位并修复
  Checking --> Running: 条件满足
  Running --> AwaitingApproval: 受控动作需要审批
  AwaitingApproval --> Running: 批准本次动作
  AwaitingApproval --> Draft: 拒绝并保留草稿
  Running --> Proposed: 形成候选变更
  Running --> Failed: 失败或结果未知
  Failed --> Draft: 保留上下文并显式重试
  Proposed --> Verifying: 用户批准应用且基线未变
  Verifying --> AwaitingAcceptance: 独立验证通过
  Verifying --> Failed: 写入或验证失败
  AwaitingAcceptance --> Accepted: 人工验收
```

该图是任务交互合同，不表示已有取消、持续后台运行或跨重启恢复。HTTP/UI缓存与持久Task/Run证据分别记录，不能由其中一个推断全链支持。发送中可切换页面，必须显示任务仍在进行；无法取消时直接说明，不提供只停止动画的假取消。

<a id="section-0b-6"></a>
### 0B.6 会话相关面板与任务看板

顶栏四入口共用「开关式」状态，但**展开载体不同**（以产品参考帧为准，禁止把终端做成右侧栏，也禁止把源文件做成进入式全屏目录）：

- **摘要（右侧锚定栏）**：打开后会话区宽度收缩；展示当前项目/仓库、会话目标、所选模型、真实生效权限、任务步骤、变更、验证、后台进程与资料来源。未知值显示未知；切换会话后不能沿用上个会话的摘要。正文与输入框保持可用。
- **变更（右侧锚定栏）**：区分“本次任务候选”“本次任务已应用”和“目录里原有修改”；提供文件列表、逐文件 Diff、冲突/审核状态。当前 `before/content` 展示仅是候选比较，不是完整仓库审查器。
- **源文件（右侧浮层 + 树展开）**：浮层覆盖对话右侧，可含搜索；目录在树中展开/收起子项，显示项目相对路径与版本/哈希；本地上传与仓库内文件不是同一个来源。不是 ⌂/↑ 进入下一层、也不是用全屏面板替换对话。
- **终端（底部停靠栏）**：停靠在对话与输入区下方（或对话主体下方），收缩会话区高度，横跨主内容宽度；必须来自真实受控执行及明确执行号。未接通时可打开底栏并诚实说明无执行日志，不得展示伪日志，页面显示日志不赋予任意 shell 权限。
- **任务看板**：归属项目，任务链接相关会话、需求、原型与 Run；待规划 → 待处理 → 进行中 → 待验收 → 已完成为目标交互，实际状态与允许动作由 EAP 统一任务规则确定。按 §0B.11 借鉴 Hermes 设计，优先复用 EAP 已有能力及合适的独立开源依赖，不直接接入 Hermes 功能，也不先自研完整调度平台。只读 `git status` Run不构成代码开发交付能力；首轮交付不要求无人值守。

### 0B.7 “原型 → 代码”重新定义：必须能改造已有 EAP 页面

<a id="section-0b-7-1"></a>
#### 0B.7.1 历史问题与当前范围

2026-10-26的结构性缺口分析及Current/Target图已移至[历史快照](records/product-plan-history.md#section-0b-7-1)，不能继续称GrapesJS、生成前基线、持久应用或Task关联“尚未实现”。当前未关闭的是实际供应商自身改页、更多组件/多文件约束和用户接受；下述合同持续有效。

<a id="section-0b-7-2"></a>
#### 0B.7.2 两条入口共用一个交付合同

“原型 → 代码”归属场景，但不强制用户从空白 Builder A 开始，也不把 Builder 设成新的第六一级入口。

- **已有仓库界面调整**：选择 EAP 项目和目标页面 → 引用现有截图/录屏/代码 → 建立可点击的布局及交互草案 → 人工确认 → 基于现有代码实施。允许先用 Vue 可点击夹具承载草案，不必等待通用拖拽编辑器完成；夹具和模拟数据明确标记。
- **新页面原型开发**：场景内打开编辑器 → 使用受支持组件设计页面与状态 → 预览 → 保存不可变版本 → 选择真实目标仓库和路由 → 同一开发/验证链路。

截图/录屏是设计参考，既不直接变成 Vue 源码，也不携带仓库授权。不能宣称可把任意已有 Vue 页面无损反向导入 GrapesJS。后续 GrapesJS 用作原型编辑器时保留其项目数据与独立语义 Schema；代码实现优先复用当前仓库组件，未知映射进入“需人工实现/确认”状态。

<a id="section-0b-7-3"></a>
#### 0B.7.3 场景界面与操作步骤

| 步骤 | 用户可见内容及动作 | 进入下一步的条件 |
|---|---|---|
| 1. 选择目标 | 项目、**本地服务确认**的仓库路径（默认共置本机）、分支/基线、目标页面；区分现有页面调整/新页面 | 仓库可在本地服务机器上读取，目标明确；无模型也可做读取和设计 |
| 2. 了解现状 | 技术栈、组件/Token、关联源码、当前修改列表；显示扫描范围与未读取部分 | 用户确认相关范围；不读整个仓库、不读取凭据 |
| 3. 设计与交互 | 原有界面对照、布局草案、属性、状态/动作；支持预览、调整及明确模拟边界 | 至少一次真实点击/切换/弹层/状态验证 |

| 5. 开发准备 | 原型版本、目标仓库、允许文件、基线哈希、实现执行器、模型、策略和预计验证命令 | 条件齐全；失败显示具体缺口，不能只跳到空聊天 |

### 0B.11 Kanban：EAP单一事实源与RK验收合同

**EAP看板属于EAP自身功能**：任务、Run、数据库、API与事件由EAP管理。
**插件边界**：看板UI以PL-01逐步转为可信贡献，当前尚非通用可安装插件；插件停用不删除Task/Run、停止核心执行或另建状态机。Hermes Kanban并非纯UI插件，参考其持久运行时与视图分层，不复制其运行系统。Hermes只作为设计/源码参考，不要求安装Hermes、接其Kanban API/SQLite/Dispatcher/Worker、嵌入React界面或同步两套状态；旧RH接入阶段取消，改为RK设计与独立依赖验证。Vibe Kanban也只作可选参考，不为界面相似更换技术栈。

采用顺序：**现有EAP能力 → 独立开源组件/库 → 按许可提取可维护实现 → 参考设计补最小缺口**。列/卡/详情先用Vue与`@eap/ui`；拖拽需键盘替代且不直接写权威状态；存储复用JDBC/Flyway；领取/重试先最小规则；HTTP/有限轮询足够时不加消息总线。Agent沿用既有适配，不自建Harness。

每项候选记录缺口、现有能力不足原因、官方来源/版本、许可/NOTICE、维护状态、Vue/Java/Spring/Windows兼容性、外部服务依赖、最小样例、运维成本与采用/拒绝理由。未调查标待评估，未找到合适库记录检索范围；项目内部源码不冒充独立库。不得为补看板先建设完整分布式调度、无人值守或市场。

| 对象或动作 | EAP 内负责边界 | 约束 |
|---|---|---|
| 项目、仓库、原型版本、验收清单 | 现有项目/仓库及原型服务 | 标签不是目录授权；资料引用不扩大允许范围 |
| 任务状态与允许动作 | 统一任务应用服务及持久化 | 核对现有 Task/Mission 后确定承载对象，不新建平行状态机 |
| Run/尝试、领取、重试 | 执行管理与最小调度层 | 一个尝试最多一个有效领取者；重复请求不能并发启动同一尝试 |
| 文件/命令/Agent执行 | 现有 Capability、执行器和适配器 | 受控工作区、参数、超时及权限由实际执行边界校验 |
| 任务事件、快照、日志与产物 | EAP API 与证据存储 | 事件描述事实；前端计数/乐观更新不是完成证据 |
| 独立验证及人工验收 | EAP验证边界及用户 | 命令退出、候选写入、构建通过、人工接受分别记录 |

目标生命周期可表达待规划、待处理、运行中、阻塞、待验收、完成及失败/取消等状态，但最终枚举与现有数据迁移需在实现审查中确定，不照抄 Hermes 的字符串。执行器回报成功后仍需验证/审阅；不再出现“Hermes 已完成 / EAP 未验收”的双系统展示。

<a id="section-0b-11-5"></a>
#### 0B.11.5 交互、API 与事件合同

- **创建与准备**：在 EAP 记录目标、项目、验收条件、设计版本及执行配置；草稿/待规划任务不因创建就自动运行。缺条件显示具体原因。
- **状态与动作**：API共享统一规则，支持查询、创建和经验证的生命周期动作；拖动是请求，服务端拒绝时回滚并解释。不可将所有状态任意拖动为完成。
- **领取与幂等**：对并发领取、重复启动、动作超时分别定义处理；结果不确定时先核对现有任务/Run，不盲目创建新尝试。
- **更新与隔离**：按项目、看板、任务范围读取快照；事件触发重读，必要时有限轮询。重连缺事件时重新取快照，切项目不显示上一项目数据。
- **执行反馈**：运行、阻塞、失败、取消请求与实际结束分开显示；未验证进程终止时不得标为已取消。页面离开不负责终止服务端已接管的执行。
- **恢复边界**：任务记录持久化、页面重开可读取，与进程跨重启恢复是不同能力。首轮不承诺自动接管遗留进程，结果未知时明确阻塞。
- **权限与验收**：复用 EAP 现有仓库授权及执行策略；模型、专家和场景选择不自动授权。候选、应用、验证、人工接受均有关联证据。

### 0C.8 增量开发关口

| 顺序 | 前后端一起交付 | 放行证据 |
|---|---|---|
| 1. 基线与会话 | 固定现有 API/事件样例，比较 Agentdown 适配与现有渲染，补同一执行的快照和恢复缺口 | 真实流式、取消、重连证据分开记录，重复和缺失事件有回归 |
| 2. 任务与审批 | 沿用 RK 看板合同，复用执行状态投影和后端审批门禁 | 同一审批从会话与看板得到一致状态，拒绝或过期能控制真实执行 |
| 3. 工作区与原型交付 | 先现有 EAP 页面、只读文件树、真实 Diff，再按需补编辑/PTY 和更多原型映射 | 可点击原型经人确认后，候选能构建、独立复核并由用户接受 |
| 4. 标准扩展与打包 | 独立验收只读 MCP、Skill 扩展及必要的宿主 PoC，按实际目标平台验证桌面包 | 许可证与依赖锁定、注册停用资源清理、真实进程与权限验证各有记录 |

顺序与 §0B.10/§0B.11 共同使用。聊天中的 P0–P5 是讨论用分期，当前排期从已有实现的验收缺口起算。实现前固定仓库版本、要读的上游文件、EAP 接入点和退出条件。许可、适配成本或故障回归达不到门槛时，继续使用现有 EAP 组件。
