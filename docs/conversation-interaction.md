# 会话与工作区交互

本设计基于 running-context.md 的个人本机定位及 runtime-workflow.md 的专家授权边界，不引入用户、租户或新的权限体系。对应原型：`prototype/console.html#chat`。

## 对象与入口

- 普通聊天：不绑定工作区，仅使用当前消息，不自动读目录、知识库、数据库资料或调用 CLI/MCP。没有模型时应明确不可用，不能伪装真实回答；原型仅提供标注的演示回复。
- 工作区：本机目录与执行上下文的组织边界，不是专家、规则或知识库的复制容器。顶部选择目前仍是客户端标记，不等于后端 EAP_WORKSPACE 已切换。
- 工作区会话：创建时绑定当前工作区，可以连续追加输入，并在已启用专家范围内准备分析。顶部切换不迁移已有会话，也不自动复制普通聊天内容。
- 执行任务：一次明确输入下的执行；一个会话可关联多次任务。任务不是会话本身。历史任务保留原输入、配置修订和实际证据。
- 分析工作台：结构化输入核对、实际执行与完整报告浏览。会话中的结果卡片指向这里，不把整个报表堆进聊天。

默认入口为会话，原有 `#sql` 深链与管理页面保留。新会话固定类型与工作区；需要另一上下文时显式新建，避免旧消息在新目录下被误解。

## 管理配置如何生效

| 配置 | 会话中的作用 | 生效条件 |
|---|---|---|
| 专家 | 明确流程与可用范围，可在工作区会话选择 | 必须已启用并授权；草稿不可执行 |
| 知识库 | 专家声明可检索的来源 | 声明不代表已读取；执行实际命中片段才成为引用，不能并集所有专家授权 |
| 数据库资料 | 可选择的脱敏元数据快照 | 必须在当前专家授权范围内，不代表连接业务数据库 |
| 规则包 | 由专家流程对确定性事实进行判定 | 不作为自然语言聊天的系统指令；缺少事实列为未判定 |
| 本地 CLI | 专家流程中的有界操作 | 注册程序不等于任意命令权限，必须通过已有操作与流程边界 |
| MCP | 专家声明、服务器信任及工具授权共同约束 | 不能因聊天提及工具名而调用；协议会话仍按执行/专家/服务器隔离 |
| 模型 | 可选的讨论与证据增强执行者 | 继续遵守端点、脱敏、预算与启用策略；显式普通聊天请求不意味着打开模型全局开关 |

不另造会话级授权表。会话保存专家选择，执行前重新校验最新授权；历史记录保存执行时版本与引用。管理配置修改不回写历史结论，也不会自动重新分析旧消息。

## 交互闭环

1. 新建普通聊天或当前工作区会话，顶部明确类型与绑定范围。
2. 工作区会话按需选择已启用专家，展开上下文即可看到其声明资源；选择本身不触发读取。
3. 发送消息追加到同一会话；消息是数据，不是对平台权限的覆盖指令。
4. 显式选择“带入分析工作台”：带入已发送的用户输入，清空旧 SQL、执行计划、资料选择和模型增强开关。核对专家及结构化输入后手动启动。
5. 执行前重新校验专家启用、修订与绑定工作区。状态变化时要求返回会话重新带入，而非静默放宽。
6. 原型生成演示任务并关联回原会话，可以打开执行记录；真实实现需持久化消息、关联与配置快照。

## 当前实现边界

本次仅更新 HTML 原型与交互定义，不代表 Vue/Java 已支持会话。原型内存数据刷新即重置；回复与任务执行都是模拟，不读取文件、不访问业务数据库、不调用模型或工具。没有制作假的流式输出、暂停恢复或自动规划。

后续实现应先建立会话、消息、执行关联与快照的最小闭环；前端独立组件/子包通过公开入口引用，后端按 controller/service/mapper/dto 分层，不继续堆进 App.vue 或现有执行控制器。
