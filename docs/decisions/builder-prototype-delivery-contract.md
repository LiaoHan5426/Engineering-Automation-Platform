- GET /api/prototype-publications/{requestId}只读返回权威版本，未找到404；GET不创建版本。request_id NOT NULL UNIQUE且无默认，旧接口/服务调用签名删除，不自动生成请求身份。
- 前端发布前持久保存冻结的原请求并读回，网络失败保留unknown；刷新/切页不重发。显式查询成功清理待核对意图；404后显示明确重试原请求，用原UUID/内容，保留之后的编辑。其他错误继续未知。未知或本地存储不可靠阻止新发布、停用及替换文档，允许保留草稿/离页。

## 唯一发布契约

`POST /api/prototype-versions`仅接受requestId、sourceRef、title、body、acceptance；requestId为调用方生成的必填UUID，sourceRef限builder-alpha/builder-beta。body必须是JSON文本，format=eap-prototype-v1，携带version=1的schema、语义root、unknownMappings=[]及grapesProject对象。保留编辑器项目和语义数据，不把HTML/CSS导出当Vue源码。

前后端均拒绝纯文本、未知格式、未注册组件或未知映射；后端SemanticPrototype另限正文160000字符、节点500及深度24。节点kind来自当前page/section/text/heading/button/input/link/list/form/select/checkbox/dialog映射，props为对象，children为数组，root须有内容；节点身份唯一，动作目标必须存在且种类匹配。发布内容先脱敏、统一换行/NFC与首尾空白后校验，再持久化。交付服务重验所引版本语义，不能只靠页面禁用按钮。

DTO/数据库已删除buttonPresses/button_presses和interaction。请求带旧字段、客户端哈希、仓库路径、模拟标签或授权信息均拒绝，不插入。没有旧文本解析、旧计数预览或legacy slot。原始正文只可作为转义后的只读证据查看，不能作为可交付设计放行。

版本id及createdAt由服务端生成，requestId由客户端提供；时间按数据库微秒精度生成，发布响应/数据库回读一致。一份版本只插入，不提供更新入口；这不是数据库防更新触发器的声明。

## 哈希与预览

当前哈希的固定字段顺序只有sourceRef、title、body、acceptance，复用Jackson UTF-8 JSON与SHA-256。版本号和时间不参与。没有历史算法注册表或双算法分支；既有合规语义版本中已存哈希作为冻结证据回读，不为旧计数内容重算/转换新设计。

语义预览由PrototypeVersionContent/PrototypeSchemaPreview完成，交互状态只在当前预览，不保存回版本或当前设计。无法解析/未知映射时明确阻塞。打开A/B乱序、关闭/卸载后返回、交付A返回时已切B均有回归。

### 可操作的表单、弹窗与任务准备

设计器可添加表单、下拉选择、勾选项、弹窗组合，配置显示名称、初始值、必填及按钮动作。按钮动作仅 TOGGLE/SUBMIT/RESET，分别操作显式选定的区块/弹窗或表单；前后端分域词表核对。预览执行必填检查、显示本地提交完成或重置字段，可打开和关闭公共 Dialog；不请求业务 API、不执行脚本、不改变已保存 Schema。没有动作的按钮只展示，不再伪造点击计数。设计时保存的是 Grapes 工程和声明式动作，发布时后端校验重复身份、悬空/错类目标、未知动作及非法选项。

不可变版本详情可明确创建待规划任务。POST /api/board/tasks/from-prototype 在原任务服务的同一事务中保存任务及版本引用，沿用 requestId 唯一约束；指纹覆盖版本、项目和文本，相同请求返回原任务，改内容返回冲突。原型版本必须在服务端存在并通过语义校验。任务创建不生成代码、不启动 Run、不授予工作区权限。页面固定并保存原请求再发送，结果不明时只允许明确重放相同幂等请求；草稿和原型发布仍是不同操作。无需新增数据库结构或第二套任务状态。

2026-11-12复核：未提交且有修改的任务草稿通过公共ConfirmBox确认放弃，取消关闭保留输入，未改或改回基线直接关闭。首次新请求直接返回明确4xx且本地意图清理并读回成功后，保留字段、释放冻结，修正后使用新requestId。网络/5xx或恢复、重放请求的后续4xx仍保留原身份与内容，避免提交成功但响应丢失时另建任务；存储清理失败继续冻结。见[验证记录](../records/validation-history.md#developed-content-review-validation)。

<a id="implementation-preparation"></a>

### 从任务准备实现

准备面板支持独立选择只读参考源码，例如候选范围外的路由宿主。`POST /api/ai/workspace/code-references` 复用生成读取的工作区授权、路径/符号链接、完整UTF-8及敏感内容检查，不使用浏览器里的截断摘录。参考文件最多6个，路径最多150字符，内容受原读取字节限额及附件单文件16000/合计24000字符约束；缺失、重复、超限和敏感内容拒绝，不截断。页面核对返回路径顺序、完整字节及范围，禁止参考与候选选集重叠；改变选集使核对失效。

核对后的内容作为明确标记 `read-only:` 的附件快照经现有任务草稿采用流程进入Chat，不添加新的TaskContext协议字段或持久准备票据。它不加入生成候选图或写入范围，亦不是执行授权。参考是操作者核对时的内容快照，发送时不会宣称它仍为磁盘当前版本；参考文件变化后应重新核对。独立Mock没有真实源码，返回现有上下文不可用错误，不伪造完整参考内容。

2026-11-11 增加显式“读取入口依赖”：`POST /api/ai/workspace/code-dependencies` 从用户选择的入口递归解析现有本地模块、明确字符串懒加载、CSS 与 JSON。解析直接复用 `ComponentGraph` 的候选依赖语法和路径解析；不存在第二套正则扫描器、持久准备状态或授权票据。每次读取均受同一授权根、符号链接、完整 UTF-8、24KB 单文件、48KB 总量及最多八文件限制；循环、缺失或歧义依赖拒绝，未支持语法明确报错，不猜测路径。文件选择仍可手工调整以支持计划新增的文件。

读取依赖会替换当前关联文件选择，界面在操作前说明；成功后展示文件核对结果，由用户明确带入草稿。修改入口、关联集合或任务版本立即使旧核对失效。在途结果不得覆盖后续编辑。这个只读动作不创建生成记录、不调用模型、不执行命令、不写源码；实际生成继续重新核对当前授权与基线。独立 Mock 对此接口明确返回源码上下文不可用，不伪造真实工作区依赖。定向回归及真实浏览器证据见[当前台账](../planning-status.md#dependency-preparation-validation)。

准备完整的待处理任务可以打开“准备实现”，填写入口及最多七个关联文件，或从既有授权文件浏览器选择已有文件。POST /api/ai/workspace/code-preparation 只读核对当前本地工作区的授权、路径、完整 UTF-8 内容与24KB/文件、48KB合计限额；返回文件存在性、摘要和字节数，不保存源码快照、不调用模型、不写文件。它和实际生成共用 CodeChangeService 的选集校验及读取函数，不建立第二份持久准备状态或授权票据。

用户改动选集后，旧核对立即失效；乱序响应不能恢复旧结果。明确采用后，将任务及原型身份、目标和关联路径一起带入现有会话草稿，再经过原有采用确认、模型选择和发送流程。实际发送重新核对任务 revision、授权与全部基线并保存生成快照，先前的只读核对不替代这些门禁。生成指令明确要求实现声明式字段/必填/选项及TOGGLE/SUBMIT/RESET，不能用点击计数替代，不凭设计发明业务 API。

## 交付单与执行边界

`POST /api/prototype-deliveries`只接受versionId，引用经语义校验的服务器版本。同一版本只有一份交付单，数据库唯一约束决定，并发冲突返回已有记录。没有仓库、权限、模型或执行状态参数；创建记录不启动Agent、不写仓库、不确认任务完成。

代码生成及受控应用继续经过现有工作区、原型/任务revision、基线、独立验证与人工接受门禁，不新增执行器、状态机或能力注册表。外部Agent边界见[工具接入](tool-integration-runtime-boundaries.md)，历史handoff不作为新发布的前置兼容入口。

## 当前多文件源码交付（V33/V34）

设计版本不直接授予源码写入。代码上下文携带targetPath入口及componentPaths（最多7个），服务端在调用模型前持久保存全部选定完整源码和hash，连同原Task/revision与原型版本；每文件24KB、合计48KB，超限拒绝，不截断。返回文件集合/顺序必须与输入完全一致。多文件图支持frontend内Vue/TS/JS及本地CSS/JSON：入口可达全部节点、无循环、无未声明相对引用。允许精确字符串指定的本地按需模块，拒绝计算路径或隐式发现；外部模块仅vue/vue-i18n/@eap/ui/@eap/runtime-client。[支持语法及边界](#route-resource-delivery)是同一合同的演进，不保留旧校验分支。

生成快照及候选响应的companionFiles为当前必填数组，单文件是空数组叶子。V33一次性补齐已存叶子元数据，运行时不回退旧格式。应用沿用唯一CodeChangeService：全基线检查、全部暂存、再检、逐文件替换、全部读回及持久结果。多文件不是OS事务；部分作用/结果不明保留UNKNOWN和工作区互锁，不能自动重发或回滚他人文件。V34同步替换交付表旧单文件CHECK，源码、时间、任务、原型及每文件验证hash仍由服务端逐项核对。

真实模型三文件证据面板及生产App交付/技术决定已通过；用户设计交互/产品接受及更多状态动作映射仍独立。见[多文件交付验收](../planning-status.md#component-page-delivery-validation)。

#### 源码写入结果未知的人工核对

V36 在原 `code_proposal` 行新增 `CLOSED_UNKNOWN` 和持久审计。能力目录列出当前授权工作区的在途、待核对及最近关闭记录；会话或看板的候选详情使用同一核对组件和 API。服务端使用本机操作者身份和真实工作区查询，逐项比对候选声明文件的写前、候选和磁盘哈希，只返回相对路径与摘要。读取失败保留互锁；关闭时在原工作区互锁下重读文件，摘要变化则拒绝该决定。

<a id="route-resource-delivery"></a>

#### 跨路由与本地文本资源交付

同一候选可由路由模块作为入口，连接多个 Vue 页面及其本地 CSS、JSON 资源。沿用显式入口和最多七个关联文件、完整 UTF-8 源码及写前哈希、精确顺序、连通性和无环约束。CSS 与 JSON 使用带扩展名的相对导入；CSS 可用独立行的带引号相对 `@import` 引用选中的样式表，JSON 顶层必须是对象或数组。项目配置与锁文件不作为页面 JSON 资源接收。

按需模块支持 `import('./Page.vue')`：参数必须是一个不含转义的普通字符串，目标必须带明确的 `.vue`/`.ts`/`.js` 后缀且已显式选择。以此建立 `LAZY_MODULE` 边，和 `MODULE`、`STYLESHEET` 一起参与原图连通和无环校验；按需加载不缩小生成前快照、应用和验证的文件集合。前端显示服务端识别的加载类型，中英文标签不重复定义 wire 常量。变量、模板字符串、拼接路径、导入选项、require、glob、远程模块和未声明目标仍拒绝。

远程样式、CSS URL、Vue 模板资产引用、二进制不纳入本切片。依赖检查限定于受支持的可静态确定语法，不是浏览器资源拦截或代码沙箱。模块加载中的状态和加载失败如何展示由交付页面实现及独立浏览器核验，不把构建成功当成运行时加载成功。

看板和会话共用候选详情，显示服务端从原候选计算出的依赖；前端不解析源码推断关系。仍用同一持久快照、受控应用、独立验证和人工决定。CSS/JSON 参与写前冲突检查、应用读回和独立验证哈希比对；现有 V33/V34 已持久化精确文件集合和交付证据，无新增表或兼容入口。

#### 不可变原型版本

版本存在服务端新表，不放进浏览器草稿、`eap.handoff`、`eap.task` 或 Mission。一行属于一个 Builder 实例，实例只取 `builder-alpha` 或 `builder-beta`。这个标签说明来源，不授予权限。

版本号是服务端生成的 UUID，唯一范围是整张版本表。不使用按实例递增的整数，也不使用全局递增序号。同一实例可以有多行；先后只看 `created_at`。

一次保存插入一行。应用只有插入、按版本号读取和按实例列表，没有更新入口，因此已插入的内容列不会被这层代码改写。再保存编辑过的草稿时插入新行。刷新页面后按版本号从数据库重新读取。服务进程重启后这些行仍在，不依赖进程内存。活草稿仍只在本机浏览器，刷新或重启都不把它变成版本。

这个保证停在应用入口。V17 建立表和唯一约束，没有防更新触发器。V18 只改表注释，写明应用只插入，并写明这些注释不是数据库防更新约束。本切片不新增触发器或权限框架。直接改表可以改变已有行；那种改动不在本切片的保证里。

这一版保存：

- 版本号、服务端算出的内容哈希、`created_at`。
- 实例标签。
- 标题和正文。
- 保存时的按钮次数。这是以后打开预览时的初始值，不是预览期间的临时计数。
- 服务端写入的固定交互说明「预览按钮使计数加一」。请求不能改这句说明。
- 操作者写明的验收条件。只随版本保存，不在这一步执行。

不保存 `mockRepositoryLabel`、`mockApproval`、`GRANTS`、仓库路径、远程地址、基线、Mission 或 Agent 标识。模拟审批仍只改本地草稿。

##### 内容哈希

哈希由服务端计算。请求体不能携带哈希；带上则拒绝，不插入。

参与哈希的只有这些字段，顺序固定：实例标签、标题、正文、保存时的按钮次数、固定交互说明、验收条件。版本号和 `created_at` 不参与。

规范化方式：先用现有 `SensitiveData.redact` 去掉口令和 JDBC 地址，再做 Unicode NFC，去掉首尾空白，内部空白保留；换行统一成 `\n`。验收条件保留提交顺序，逐条做同样的处理，空条目去掉。按钮次数是非负整数。然后按上述固定字段顺序，用项目已有的 Jackson 把字段编成没有多余空白的 UTF-8 JSON。字段顺序仍由代码显式排列，不依赖调用方的 JSON 排版。内容哈希是这组字节的 SHA-256 十六进制。

因此保存下来的标题、正文和验收条件可能已经是脱敏后的文本。库里不另存一份原文。前端预览展示服务端返回的这些字段。

因此内容不可变指的是这条规范化结果和当时写入的哈希不变。两次请求的原始 JSON 排版、键顺序或换行符不同，只要规范化结果相同，哈希就相同。

保留历史哈希，新保存使用 Jackson。已经插入的行保留当时写入的内容和 `content_hash`；读取返回这一列，不按新算法重算，也不回写。应用没有哈希校验入口，因此不为历史内容增加算法注册表或兼容框架。

新保存按上面的固定字段顺序交给已有 Jackson 编码。单元测试观察到：引号、反斜杠、换行、制表符、普通 Unicode 以及 `\u0001` 与原先手写转义的字节相同；退格 U+0008 和换页 U+000C 不同，手写转义是 `\u0008` / `\u000c`，Jackson 是 `\b` / `\f`。这不能推出所有历史内容都能用新算法重算并得到原哈希。应用没有更新语句。

保存和重开使用同一份规范化内容。库中保存的是脱敏并规范化后的字段，哈希对这组字段计算。重开时展示的标题、正文、按钮次数初始值、交互说明和验收条件就是这组字段，不另做一套展示用的原文。固定交互说明只由服务端写入上述常量，不接受请求覆盖。

##### 预览隔离

页面上有两份预览。活草稿预览绑定浏览器草稿，按钮点击改的是草稿里的计数。版本预览是另一份临时状态，只在打开某个版本后出现。

打开版本时，页面另建这份临时预览。初始标题、正文和按钮次数来自该版本已保存的规范化内容。按钮点击只增加这份临时计数。

打开、关闭、切换版本或卸载后，更早的版本响应不能重新打开预览，也不能覆盖后来打开的版本。生成交付单时先记下当时的版本号；返回结果只写进仍停在该版本上的预览。关闭或切走之后，迟到的交付结果不能把旧单显示回来。版本列表读取失败时显示错误，保留草稿和已经显示的版本，不用空列表代替失败。这些保护使用组件内部的请求序号，不另建状态框架。

临时状态不写回版本，也不调用保存草稿，因此不覆盖活草稿里的标题、正文、按钮次数、模拟仓库标签或模拟审批。离开该预览后，临时计数丢弃。再次打开时，按钮次数回到版本里保存的初始值。

#### 交付单

交付单是独立记录，不是 `eap.handoff` 的新列或新状态。生成它不插入交接，也不修改已有交接的 `summary`、来源或四个固定状态。

一行交付单只引用一个原型版本。数据库对该版本号有唯一约束。并发插入冲突时返回已有记录，不向调用方报成失败，也不插入第二行。按钮在请求期间不可再点，只避免同一次点击重复提交；它不代替这条约束。

请求体只允许版本号。仓库路径、远程地址、基线、模拟仓库标签、授权或审批字段都拒绝，并且不插入。交付单没有这些列。展示时写明仓库未绑定、基线未记录、Agent 未调用。这一步不做路径解析、远程仓库验证或新的授权机制。

已有交接保持原样。不为旧行补版本，也不把旧 `summary` 改写成交付单。

交付单本身仍是记录，不是执行。它不调用模型，不调用 `CodexAdapter`，不写目标仓库，也不把 Mission 标成完成。
