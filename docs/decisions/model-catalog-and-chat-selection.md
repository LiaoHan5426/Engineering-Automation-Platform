# 模型目录与会话选择

日期：2026-10-26。承接桌面工作台初步调整。本轮使用已有 Spring AI 调用链；未新增 Provider 框架。

## 连接、目录、使用配置和会话

连接表单只保存名称、端点、API Key、启用状态及默认连接标记。创建连接不要求模型，也不填入预设模型。

模型目录是独立配置：保存新凭据后前端明确请求同步，也可手动同步或添加模型 ID。允许列表和新会话默认模型必须通过单独保存生效。新发现的模型不会自动启用。

不提供原有单模型字段的兼容入口：旧存储中的 `model` 不被转换为目录、允许列表或默认模型；凭据保留，但需要重新选择模型。Spring AI 环境属性不再自动生成一条可选连接。

既有连接 API 的输入移除 `model`；会话绑定必须同时指定 `connectionId` 和 `model`。新增：

- `POST /api/ai/connections/{id}/models/refresh`：通过服务端凭据读取目录，返回缓存、同步时间和错误代码。
- `POST /api/ai/connections/{id}/models`：保存 `models`、`allowedModels`、`defaultModel`。
- `GET /api/ai/connections`：返回凭据存在标记、目录和使用配置，不返回密钥。

目录同步仅请求配置地址下的模型元数据，不生成内容；请求有连接及请求超时、响应大小上限，禁止跟随重定向。错误不包含响应正文或凭据。失败保留上次成功目录与时间。目录包含已发现及手动添加项，不保证每个 ID 都能执行当前任务。

目录接口不能证明模型支持哪些推理参数。因此不再通过域名和模型名猜测。默认不发送推理参数；用户可按服务商文档为模型明确配置 low、medium、high 档位。服务端发送前校验允许列表和档位，未知档位不放行。当前未实现额外思考协议、token budget 或 xhigh 等值。

新会话使用显式配置的默认连接及默认模型。改变默认项影响后续会话；已有会话保留其所选模型。修改凭据或端点清理对应模型配置，已有会话重新确认后才能继续。移出允许列表或停用连接后，服务端拒绝发送。

## 对话行为调整

- 输入框模型列表只列出已启用连接中的允许模型，并展示连接名称。
- 同一连接下的不同模型使用不同缓存客户端。
- 首次输入可直接发送：创建会话，绑定所选模型，再提交请求；失败保留草稿。
- 切换连接或模型先确认，并说明服务端上下文清空、本机历史保留。
- 同一模型的凭据版本变化可重新选择并确认；不静默切到其他模型。
- 会话各自保留指导、附件、任务模式和推理参数；返回设置再回对话时恢复当前会话。原型版本引用进入新的待发送上下文，不自动发送。
- 消息历史记录当时选用的连接名称、模型和推理参数。
- 输入框的三个专家选项明确称为“内置指导角色”，不冒充专家管理器中的动态专家配置。
