## 目标与当前事实

上一阶段完成的是隔离工作区中的独立表单、真实文本优化与限定源码技术交付，见[验证记录](../records/validation-history.md#textarea-source-ai-optimization)。本阶段把已实现的优化 API 接入正式看板新建任务，沿用原任务创建服务与请求身份；不另建任务模型或创建通道。

当前入口是 [PreviewBoard](../../frontend/apps/web/src/features/shell/PreviewBoard.vue)，创建函数保存原请求并调用 `runtimeApi.createBoardTask`，包含项目、标题、任务目标、验收标准、创建列及可选会话。正式表单使用公共 Dialog/Input/Textarea/Select/Checkbox/Button。已有领域未定义“功能开发/问题修复”类别，本方案不把类别转成优先级，也不为展示效果新增数据库分类。

## 已确认的效果

- 保留看板内新建弹窗。项目与创建位置并排；窄屏单列。标题、目标与验收标准保持独立；只有目标旁有“AI 优化”。
- 优化先展示建议，明确采用后才替换目标，验收标准保持原文。生成期间编辑、取消、关闭及迟到响应沿用草稿保护合同。输入目标允许4000字符；优化服务返回上限仍为2000字符，不改变服务预算。
- 待规划允许先记录不完整目标；就绪要求目标与验收标准。关联当前会话继续为可选操作，实际页面仅在已有会话时提供。
- 创建成功读回后返回看板并定位新任务；创建不自动启动执行。关闭有修改的草稿先确认丢弃；网络结果不明时冻结原提交并以同一 `requestId` 核对，避免重复创建。

## 确认后的实施与验收

1. 在现有看板功能域内接入 runtime-client 已有优化方法，使用公共 UI，不复制基础控件或修改通用语义预览动作。
2. 保留任务创建唯一服务及已有请求持久化/重试路径；优化的请求身份与任务创建身份分别持有，互不替代。创建期间冻结原稿、取消旧优化，迟到建议不覆盖。
3. 定向验证明确采用、原文漂移、取消与关闭、首个明确4xx后的修正、响应丢失后的同身份核对，以及保存后任务读回。覆盖1440/390、键盘焦点和未保存状态。
4. 在隔离测试库执行正式创建→读回→同请求去重，不清理日常库；真实模型优化单独取证。同步[主方案](../EAP-frontend-architecture-adjustment-v1.6-Spring-AI.md)、[台账](../planning-status.md)与验证记录；技术检查和用户产品接受分别标记。

## 已有任务目标编辑扩展（定向技术验收通过）

用户于2026-11-13通过交互问答确认当前效果。仅在任务详情的“准备”页签目标旁增加优化入口和建议预览，保持项目/会话、优先级、目标、验收标准、备注和保存的既有结构。[效果稿](../../backend/target/board-edit-ai-preview-20261113/preview.html)及[1440/390模拟检查](../../backend/target/board-edit-ai-preview-20261113/validation.json)仅用于效果审阅，不替代正式实现和实际业务验收。

- 明确采用只替换本地目标草稿；验收标准、备注和优先级保持原样。保存继续调用唯一的 `updateBoardTask`，携带原草稿 revision；采用建议不自动保存或启动 Run。
- 优化绑定项目、任务、目标原文与 revision。编辑目标、切换任务、关闭详情、保存、进入执行或出现新 revision 时取消旧请求并使迟到建议失效。执行中、忙碌和版本冲突时暂停优化与采用。
- 延用按任务保存的草稿缓存和原冲突处理：409 后保留全部本地草稿，核对最新值，再明确选择使用最新或保留草稿；建议不暗中更新 revision 或覆盖冲突字段。
- 新建与详情共用一条可取消优化执行路径，以任务/项目/原文/revision/编辑代次隔离建议；编辑后恢复原文仍使旧建议失效。45项定向前端检查、类型/边界/构建及1440/390实际App验收通过。真实优化HTTP200、采用前后SQL保持原目标、明确保存读回、两次真实409及keepDraft/useLatest核对保存通过；取消/漂移/关闭/切任务为显式故障注入，逐次等待同UUID真实DELETE204再释放迟到响应。详见[编辑验证记录](../records/validation-history.md#board-task-ai-editing)。
