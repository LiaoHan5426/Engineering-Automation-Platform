# 扩展职责边界决策

状态：以下核心边界已由用户确认；具体切片仍须按授权实施，目标设计不表示已经交付。

| 对象 | 职责 | 不承担 |
|---|---|---|
| Workspace Plugin | 可信 UI 贡献、实例配置、生命周期 | 默认工具授权、后台任务所有权 |
| Skill | 版本化按需指令、资源、能力依赖 | 直接启动任意进程 |
| MCP | 协议初始化、发现、工具调用与会话 | 仅由登记工具名证明可执行 |
| Capability | 受控执行接口、策略与结构化证据 | UI 插件安装或任务目标判断 |
| Expert | 目标：可在对话中选择的专业指令与资源配置；现有静态 DAG 是可复用的确定性流程实现 | 以角色声明自动授予工具权限，或要求所有专家先实现固定 DAG |
| Rule | 对事实的声明式判断 | 工具执行或持久化调度 |
| Knowledge | 来源、索引、检索、引用与范围 | 自动成为可信执行指令 |
| Mission | 目标、规划/观察/验证循环、审批与恢复 | 依赖聊天页面存活 |

优先保留现有 Handler 注册、专家图、规则、知识全文检索、两级 CLI 和 MCP 授权/隔离。首版 UI 插件静态打包，Manifest 仅映射受信模块；不引入第三方动态执行代码或市场。权限申请与授予分开。Plugin Registry 与 Capability Registry 服务不同职责，不合并为万能接口。

已确认：保留合理的 Capability、Expert、Rule 实现；Skill 首版仅可信本地导入并保留版本、来源、依赖和作用域；Builder 首版仅 Vue 3/Vite，仓库适配采用可扩展接口；Mission Board 是独立插件，Runtime、调度、持久化和审批属于平台核心；首版仅可信内置插件，不开发市场或任意第三方动态加载。

v1.6 补充：Spring AI 负责通用模型、工具调用和记忆，EAP 负责工程权限、执行证据和独立验证；Codex 等外部编码 Agent 继续独立适配。S1 已实现，限制见 [S1 Chat 设计](s1-chat-spring-ai-design.md)。S2 P0/P1 原型已按已确认的 [S2 插件契约](s2-workspace-plugin-contract.md) 实施。P2 先增加未执行的交接记录，见 [P2 交接契约](p2-handoff-contract.md)。Mission 第一切片只建立未执行任务壳，见 [P2 Mission 契约](p2-mission-contract.md)。只读 git-status 单步执行已按 [Mission 单步执行契约](mission-single-step-execution-contract.md) 实施，并收敛到共享运行时和单一 Git 入口。未知执行会阻塞；人工解除机制尚未实现，不能算可恢复 Mission。调度、审批流、自动续跑和独立验证仍后置。不恢复历史沙箱排查。

仍待具体实施时确认：隔离 PostgreSQL 集成验证的专用环境。知识检索暂不引入向量数据库，待质量评测决定。

## 2026-10-24 产品主路径纠偏

用户明确的主要使用流程是：输入需求 → 引用文件/上下文 → 选择协作专家 → 选择模型或已有 Agent、推理强度和审批模式 → 发送 → 查看执行、结果与变更并验收。模型设置、SQL 工作台、Builder、交接记录和 Mission 都不能代替这个主流程。

专家的产品含义是可配置的专业角色/任务指令及相关知识、规则、工具依赖，近似 Agent profile / 会话角色配置，不等于为每个专业写 Java 业务入口。当前 ExpertManifest 只有 steps/edges 等配置，属于静态流程；它尚未实现可附加到聊天的专家角色。保留已有 SQL 解析、规则、知识及流程能力作为可调用工具，不强制通用对话先进入 SqlExpertService，也不为每个专家造一套执行器。角色提示不是授权。

聊天输入区需要可见的文件与专家引用、模型/执行目标、推理强度和审批选择；所选执行目标不支持的选项应禁用或说明，不能装作生效。首版可只执行一个配置专家；不因界面允许组合引用而先建设多 Agent 调度。推理强度只在目标支持时传递，审批选择映射目标的真实策略，不由角色文本或用户提交布尔值代替。

原型到代码是独立的工程任务场景，可优先用来跑通真实交付，但不是通用仓库任务的前置。当前 Builder 仅标题/正文/按钮的受限 Vue 示例，不等于用户已经认可的完整原型设计器。已有不可变版本和交付单是可选上下文来源，不要求普通需求先生成版本、Handoff、Mission 或完成其数据库验收。

实施顺序改为先验收上述主流程的可点击交互，再以一个真实仓库需求纵向贯通已有 Harness、文件上下文、一个专家和结果审阅；并行隔离、持久调度、复杂审批、跨重启恢复、完整原型编辑器和更多供应商均后置。确定性优先表示优先选用可靠工具，不表示所有用户请求强制经过 SQL 固定管线。此处记录产品方向，不在本次文档更新中改业务代码或运行 Agent。
