## 已确认的交互

- 保留名称/状态筛选、数量、空态和只读详情；详情内明确进入编辑。
- 只编辑目标和验收标准，两项均必填、非空白且各最多2000字符；名称、身份、状态、优先级和摘要只读。
- 底部“AI优化”与“取消”“保存更改”同级，一次优化任务目标与验收标准；请求中支持取消、失败后重试，建议区分别展示两项建议，明确采用建议或保留原文。采用只更新两项编辑草稿，不自动保存。
- 取消、任一字段编辑（含改回同值）、关闭及重开均使旧建议失效；任一字段空白或超2000字符时阻断优化。两项输出分别校验非空白且最多2000字符，失败保留全部草稿并允许重试。
- 效果稿的AI为明确标注的本地模拟，无HTTP/模型；正式接入复用既有优化能力和独立取消机制。既有单项`text`的2000字符纯文本合同继续用于原调用方；本片为两字段各2000单独建立严格结构化合同并复用执行基础，不将单字段结果复制为两字段，不靠标题拆分文本，也不截断输出掩盖格式或长度错误。
- 保存通过校验后只更新当前预览的对应记录；重新查看及编辑读取该值，其他记录和筛选保持。无看板任务写入；重开预览恢复设计初值。
- 取消、关闭和 Escape 在草稿变化时先确认放弃或继续编辑；未变化直接返回详情。校验失败保留输入，错误位于弹窗内并定位首错。
- 1440/390px均可访问末端操作；覆盖键盘焦点约束、确认后回焦及列表操作焦点恢复。模拟边界在效果稿外层明确说明。

## 实施与验证关口

效果稿已获用户交互确认，按以下合同实施；实际结果仍须由定向测试与浏览器验证建立。扩展现有任务列表与公共 UI，复用 Dialog、ConfirmBox、Button 和主题 token；不新增业务状态机、持久化或通用脚本解释器。

- `task-list.props.editable` 为可选 boolean；缺省为只读，显式 `true` 开启本地编辑，非 boolean 为非法协议。既有七字段记录与0–30条上限保持，编辑只涉及目标、验收标准。Grapes显式属性、前后端校验、语义预览及生成材料同步。
- 新增 `POST /api/ai/task-detail/optimizations/{requestId}`，输入 `{goal, acceptanceCriteria}`，每项非空白且最多2000字符；响应 `{goal, acceptanceCriteria, connectionId, model}`。`DELETE` 同一地址独立取消，失败和迟到结果保留原草稿；双字段模型输出只接受包含两项字符串的完整JSON，额外字段、重复键、截断、空白及超长均阻断，无标题拆分或截断回退。
- 双字段优化与既有单字段优化复用同一模型选择、主体隔离、60秒超时、取消与全局8/主体2并发上限执行路径，分别保留明确输入输出合同；无会话、工具、任务写入。旧看板单字段调用方保持原语义。
- 预览内存记录与编辑草稿分离，明确采用更新两项草稿，明确保存更新对应本地记录；清空筛选不重建记录，重开预览/切换设计身份/停用才恢复设计初值并清理请求。预览保存及AI请求均不修改设计工程或不可变版本。

源码验收暴露了脱敏残片仍可进入候选的问题，本片补齐 `CodeChangeService` 对每份解码源码的 `[redacted`/`«redacted` 标记准入，整份提案按既有 `INVALID_CODE_PROPOSAL` 失败，审批前不保存候选。实际生成使用 `requestEpoch/capturedEpoch` 表达数值请求代次。该补丁保留全局凭据防护；代码答案仍经过 `redactComplete`，通用敏感字段误判及静默改写的根因并未在本片重构，命名约束也不作为通用根因修复。该段为本片完成时的历史边界；后续[两任务批次](dsh-ai-team-batch.md)已移除代码答案的静默改写，新增严格解码检查和局部源码引用判断，并同步相邻源码快照入口，111项离线回归通过。复杂含糊表达式仍保守失败，真实模型整链未在后续批复验。

定向验证包括字段边界、草稿与已保存本地记录隔离、放弃/继续、同值还原、记录/预览身份切换和停用清理，以及原设计和不可变版本未改变。随后验证实际设计保存重开/发布、同一版本关联任务的真实模型候选、明确应用、独立检查与哈希、1440/390源码行为及技术决定刷新读回。模拟检查、真实供应商、技术 ACCEPT 和用户产品接受分别记录。
