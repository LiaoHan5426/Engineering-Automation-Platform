# 前端原型与交互合同

本文件是旧知识库IA评审、导航重构和会话交互说明的统一入口。当前实现和后续顺序以 [roadmap](roadmap.md) 为准，产品目标不代表已经实现。

## 当前原型与产品边界

唯一保留的 [控制台HTML原型](prototype/console.html) 是独立演示页面，内嵌脚本提供模拟状态与交互。它仍由 scripts/test-conversation-prototype.cjs 引用，不能当作无用脚本删除。已结束的知识库结构提案HTML已被主原型覆盖，退役后不再并行维护。

- 原型的回复、任务推进、桌面能力与状态标记不能证明后端执行、模型调用、目录切换或持久化。
- Vue控制台已有管理、SQL分析与运行记录能力，是否完成某项以实际代码和测试为准；不能从原型的按钮存在推断实现。
- Spring AI 2.0.2 已有后端ChatClient、工具调用与ChatMemory，但 EngineeringChatService 尚未接入Chat工作台；不能显示“模型已连接”来替代真实调用证据。
- v1.6 的最小接入范围、拟议 HTTP 合同和交互验收见 [S1 设计](decisions/s1-chat-spring-ai-design.md)。本文件继续维护跨工作台交互合同，不另建平行原型路线。
- 预装Chat、Builder与独立Mission Board属于工作台插件目标。Mission Runtime的生命周期、审批与持久化属于平台核心，不能依赖聊天页面或插件存活。
- Expert DAG是流程编辑器，不是GrapesJS页面设计器，也不是动态自主规划。

## 会话、工作区与分析工作台

| 对象 | 交互合同 |
|---|---|
| 普通聊天 | 不自动读取目录、知识库、数据库资料或调用CLI/MCP；没有模型时明确不可用，演示回复必须标注模拟 |
| 工作区 | 本机目录和执行上下文的组织边界；顶部客户端选择不等于后端工作目录已切换 |
| 工作区会话 | 新建时绑定工作区；切换顶部工作区不能迁移旧消息或静默更改旧会话上下文 |
| 执行记录 | 一次明确输入对应一次运行；会话可以关联多个运行，消息本身不是执行生命周期 |
| 分析工作台 | 结构化输入核对、显式启动和完整报告浏览；聊天结果卡片可跳转，不能把整个报表堆进消息 |

原型默认会话入口与旧SQL深链是交互演示，不是永久写死的两种平台模式。带入分析时清空旧SQL、执行计划、资料选择和模型增强开关，要求用户核对后显式执行。执行前重新核对专家启用、修订、授权及绑定工作区；过期配置不能静默放行。

管理配置在平台层复用，不为每个工作区复制专家、规则和知识库，也不因消息提及工具名授予权限。草稿专家不可执行；知识库只在真实检索命中后形成引用；数据库资料是脱敏快照，不代表连接业务数据库；规则基于确定性事实，缺少事实须列为未判定。MCP还需服务器信任、专家声明及工具授权，执行会话隔离仍在后端。

## 导航与信息架构

旧方案从“同页堆叠”演进为页签，再演进为集合/条目/工作面的层级导航；不再同时维护三种方案。原型使用hash表达位置，示意合同为 `#<area>`、`#<area>/<itemId>/<face>`、`#<area>/<mode>`；具体有效路径以原型路由实现为准，不宣称Vue已使用Vue Router。

- 集合页、对象条目页与集合级检索/词表模式分别表达作用域；检索不能依附于任意选中的知识库。
- URL与渲染状态保持一致，刷新及前进/后退不应悄悄重置当前对象。选择高亮与检查器状态分开，换页不会抹掉当前条目的高亮。
- 工作入口与配置管理分组，管理页面不能与主任务争夺同等导航权重；实际插件导航在后续授权切片落地。
- 页签用于同一对象的不同面，抽屉承载新建/重命名/新增文档等短事务，模态承载破坏性确认；不以弹窗或独立窗口承担主导航。
- 抽屉有未保存拦截和焦点返回；删除确认显示影响面及引用阻断，409不能显示为成功；模态不调用window.confirm或Electron系统业务对话框。
- 结果反馈留在动作对应上下文；提交后高亮新增条目。无选择对象时给出明确空态，不能摆出无意义表单。

### Vue 工作台五入口（2026-10-26，已并入原 desktop-workspace 决策）

复用当前 Vue Renderer；未交付 Electron。活动栏固定为 **code · 编程**、**work · 办公**、**场景**、**专家**、**设置**。

- 编程：工程对话及分析工作台；会话列表由已有工作区管理。
- 场景：「原型 → 代码」；须显式选择已保存 Builder 版本才能进入编程对话，不自动发送。列表失败时阻止交接并提供刷新。
- 专家独立呈现；模型、插件、规则、知识、数据库及能力管理归设置。
- 办公为待接入空态，不模拟业务执行。插件禁用后对应入口回退到当前可用入口。
- 五入口切换记住本次页面生命周期内各分区最后访问页；聊天 / 原型 A / 原型 B 首次访问后可保留实例（最多三个），禁用插件或关闭应用时释放，不宣称跨刷新恢复未保存编辑。
- 输入框：模式、写入策略、模型和推理强度在操作栏；模型管理入口在设置。连接与模型目录拆开，见 [模型目录与会话选择](decisions/model-catalog-and-chat-selection.md)；ChatGPT 账号通道见 [账号登录](decisions/chatgpt-account-sign-in.md)。
- 界面与模拟边界须人工验收；构建/单元测试/HTTP 成功不替代真实模型和业务验收。

## 执行与证据展示

运行列表、输入区、工具/节点时间线和检查器使用一致的当前运行状态。确定性发现、模型建议、未判定规则、引用及错误分别展示；模型文本始终是待验证观察。

- 模型显示未配置、已配置未验证、调用失败或成功，不把配置保存成功当连接成功。
- 执行、审批、独立验证三类状态分开。退出0不代表文件任务完成；没有独立验证不能显示VERIFIED。
- 路径、授权范围、步骤/工具、耗时、错误、Artifact引用及结果范围可追溯；不把假进度条或前端计时器当后台执行。
- 空态、加载、失败、离线、部分结果及过期响应均明确；不能用旧结果冒充新运行结果。
- 浏览器运行目标只提供已实现的HTTP与页面功能；Electron目录选择、系统通知和preload等按 [桌面设计](desktop-spec.md) 标为目标，不模拟真实系统权限。

## 原型到实现的验收

原型先验证可交互流程及模拟边界，经过交互审阅后按 [开发指南](agent-development-guide.md) 小步接入。后续Builder需支持手工GrapesJS编辑、语义Schema、组件映射、Vue交互预览及版本保存；HTML/CSS输出不能直接视作可维护Vue源码。

原型未修改时不因文档整理重跑所有UI测试；修改真实Vue交互时，从仓库根使用实际配置的命令：

```powershell
rtk proxy pnpm --dir frontend typecheck
rtk proxy pnpm --dir frontend test run
rtk proxy pnpm --dir frontend build
rtk proxy pnpm --dir frontend check:boundaries
```

现存浏览器原型检查脚本的运行条件见其源码，不能用机器私有目录中的verify-console.js作为仓库必过命令。历史文档曾记录328、405、484、498项原型断言及截图核验，这些只属于当时的原型演进记录，本次未重跑、不能作为当前Vue或Agent功能验收。

前端共享包与目录边界见 [module-layout](module-layout.md)，后端API见 [运行时参考](backend-architecture.md)。本文件合并旧评审规则，不授权开发插件、Mission、Builder或真实模型调用。
