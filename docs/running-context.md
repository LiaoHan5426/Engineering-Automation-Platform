# 运行环境定位：个人本地单机与本地服务

> 本文是**约束性**文档，不是背景介绍。任何设计、文档与原型改动都不得与它冲突；
> 发现冲突时改设计，不改这里。
>
> 2026-10-27 已并入原 `docs/decisions/local-service-and-installer.md`（本地服务、一体安装、非 SaaS）。

## 一句话定位

**这是一个装在个人机器上、由一个人操作、只在本机运行的工程分析控制台。**
Java `eap-runtime` 是**本机本地服务**，不是模型厂商式远端多租户后端。它不对外提供多租户服务，
没有第二个用户，也不需要为「被部署到公有云代管他人仓库」做准备。

这不是「现阶段先这样，以后可能上云」——恰恰相反：**上云 / 隔离云 VM / 远端多租户代持异机路径与密钥
是要被明确否决的方向**，因为整个平台的价值主张（确定性优先、脱敏、专家授权、进程执行）都建立在
「操作者拥有这台机器和被分析的代码」这个前提上。

## 组件职责（本机）

```text
用户机器
  Python 安装/引导（规划）──► 初始化 DB / 配置模板 / 启停
       │
       ├─► UI（本机浏览器或后续桌面壳）
       └─► Java 本地服务 ──► 本机数据目录（连接、会话、资料、工作区绑定）
                         ──► 本机仓库（ProcessExecutor）
                         ──► HTTPS 外呼模型厂商（密钥不出本机）
```

| 组件 | 职责 | 非职责 |
|---|---|---|
| Python 安装器 | 一体安装、引导初始化、启停本地 Java/UI | Agent 循环、持有业务密钥作为运行时、替代 Capability |
| Java 本地服务 | 专家/场景/Skill/知识等资料；会话；模型连接；同机命令执行 | 多租户云代管他人密钥/路径；公有云代跑任意用户盘 |
| UI | 连本地服务；展示与操作 | 把仅浏览器 `localStorage` 路径当成进程 cwd/写权限 |
| 模型厂商 API | 外呼推理 | — |

**产品默认共置**：UI 与本地 Java 在同一台机器；同机 `ProcessExecutor` 执行 git/rg/已登记 CLI 合法。
纯「异机浏览器 ↔ 远端 Java」**不是默认产品形态**。可选 Electron 壳增强选目录等体验，不否定本地
Java 存连接与执行命令。

## 边界重写（替换易误导旧口径）

| 旧口径（过度外推） | 纠偏后 |
|---|---|
| 「服务端」不存 GPT/DeepSeek 连接 | **本地服务可以存**于本机数据目录；禁止的是远端多租户代管密钥 |
| 「服务端」不存目录授权 | **本地服务可绑定本机工作区**；禁止的是远端实例持久化**另一台电脑**的路径当授权库 |
| 必须双轨：同机 ProcessExecutor + 异机本机桥并列为产品 | **默认共置**，ProcessExecutor 为一等执行面；异机/纯远端非默认 |
| 调模型必须迁出 Java | **本地服务调模型合法**（含 Spring AI）；密钥留在本机 |

仍成立的约束：

- 浏览器标签 / `intendedPath`（无桥或本地服务确认）不是写权限。
- 不能静默把授权扩大到父目录或整盘。
- 外部模型输出须独立验证（diff/构建/测试），不能当作完成事实。
- 文档与 UI 不得把「未共置的远端 Java 路径」冒充用户仓库。
- `storesUserDirectoryGrants=false` / `POST …/grants → 405` 表示**拒绝浏览器/远端多租户授权库 POST**；本地服务仍可通过进程绑定根绑定本机工作区。
- 生产装配：`eap.runtime.authorized-root` 与旧键皆空时，`RuntimeWorkspace.colocated` **默认绑定到检测出的进程工作区**（不扩大到父目录）；显式冲突仍拒绝。产品 UI 已按本地服务口径展示（2026-10-27）。

## Python 安装器范围（首轮目标）

- **已有脚手架（2026-10-28）**：[`scripts/eap_bootstrap.py`](../scripts/eap_bootstrap.py) 探测 Java/Node/pnpm、写入 `.eap/local-bootstrap.json`、打印启停与健康检查；明确非 Agent 宿主。
- 仍缺：检测/创建可 gitignore 的工具 venv（**不**将 `.venv` 提交为产品运行依赖）；数据库或内嵌库迁移；模型 API Key 写入本机服务配置；一体拉起 Java/UI 与失败重试。
- 明确不做：云部署编排、多租户安装器、隔离云执行环境、Agent/调模型宿主。

仓库 [`scripts/README.md`](../scripts/README.md) 保留维护脚本用途；安装器脚手架已落在 `scripts/`，仍不得变成 Agent 主运行时。

## 与 Cursor / Codex 的关系

- 对齐：命令与工作区在**用户机器**上；本地服务扮演桌面产品中的本地运行时角色。
- 不对齐：厂商云账号层、Cloud Agents / 隔离 VM。

## 为什么这条定位容易被丢掉

写文档时会不自觉借用服务端产品的语汇——那些词各自带着隐含前提：

| 借来的词 | 它悄悄带进来的前提 | 在本项目中是否成立 |
|---|---|---|
| 审计 / audit | 多个责任主体、需要追责与不可抵赖 | **不成立**——只有一个操作者 |
| 认证身份 / authenticated identity | 有账户体系，需要区分调用者 | **不成立**——本地可信操作者 |
| 权限矩阵 | 给不同的人分配不同的权 | **不成立**，但见下文：边界仍然要划 |
| 部署 / deployment | 有一台要发布上去的服务器 | **不成立**——安装到本机 |
| 并发限量 / 配额 | 多用户争抢资源 | **不成立**（限量的真实理由另有其事：防失控输出） |
| 对外接口加固 | 接口会暴露到不可信网络 | **不成立**——只监听 loopback |
| 「服务端不存本地信息」 | Java 是远端 SaaS | **不成立于默认产品**——本地服务存本机配置合法 |

## 定位决定什么：三张清单

### A. 该删掉的（按服务端假设长出来的东西）

- 用户、账户、角色、租户、会话归属到「人」的所有概念
- 鉴权中间件、登录态、对外服务加固、「加认证前不要公开接口」这类提示
- 多实例、水平扩展、容器编排、健康检查给编排系统用
- 云端凭据分发（下发 scoped key 那套）
- 「Web 部署」作为一个**远程**投放目标
- 隔离云 VM / Cloud Agents 执行环境

### B. 该保留、但理由必须重写的

| 机制 | 错误理由（不要再用） | 正确理由 |
|---|---|---|
| MCP 服务器 enable / trust 双开关 + 工具白名单 | 防止其他用户越权调用 | **你装进来的第三方 MCP 服务器默认不可信**；信任是你对「这个外部进程」的判断 |
| 专家必须声明 `mcpTools` 才可用 | 权限矩阵 | **第三方专家包的权限边界**：拿什么能力必须显式写下并被人看见 |
| MCP 会话按 `(执行, 专家, 服务器)` 隔离 | 「审计无法区分发起人」 | **状态与游标污染**：串了会静默漏读 |
| 知识访问 deny-by-default + 逐条引用 | 合规 | **模型与专家都不能自证**，引用是让人能核 |
| 脱敏（连接串、输出截断） | 防止泄露给其他租户 | **防止泄露进模型请求和导出产物** |
| 主进程校验每个 IPC 入参 | 防被攻陷的渲染页 | 渲染内容含**别人的仓库、模型输出、MCP 返回**，是不受信任的数据 |
| 操作记录只记动作、不记重绘 | 审计合规 | 见下节：这份记录要能回答「我做过什么」 |
| 进程绑定根 / 工作区绑定 | 「远端授权库」 | **本机本地服务**限制命令 cwd 与可写范围，防失控扩大到父目录或整盘 |

### C. 该加强的（本地场景反而更需要的）

- **可回溯与可撤销**：责任主体唯一，「撤销」在单人场景是可以给的权利。
- **第三方隔离**：这是本地场景的主要风险面。
- **本机凭据存放**：keychain / 环境变量 / 本地服务数据目录；**导出与分享配置时要能自动剔除**。

## 威胁模型：主体换了

```
服务端场景（不是我们）：          个人本地场景（我们）：
  风险来自 别的人                   风险来自 我引入的东西
  ├─ 外部用户登录                   ├─ 第三方专家包（配置即代码）
  ├─ 越权访问他人数据               ├─ 第三方 MCP 服务器（外部进程）
  └─ 事后追责                       ├─ 模型输出（不可信观察）
      → 鉴权 / 审计 / 租户隔离      ├─ 被分析仓库里的内容（不受信任数据）
                                    └─ 出站：模型请求、导出、分享
                                        → 能力边界 / 第三方隔离 / 脱敏 / 可回溯
```

结论不是「安全可以放松」，而是**重心转移**：横向的、针对人的防护删掉；面向引入物与出站的防护加强。

## 语汇约束

**不再使用「审计」这个词。** 用**操作历史 / 活动记录**。

理由不是字面洁癖：audit 在合规语境里绑定了「多主体 + 追责 + 不可抵赖」。而「操作历史」直接指向真实用途：

> 回答「我做过什么、为什么这次结果和上次不一样」，并支撑撤销。

由此：**操作历史应当能记下「改之前是什么」**。既有的不变量（切页签不写记录）继续成立。

**不再使用「部署」指发布到远程。** 两种投放目标都运行在本机：

| 目标 | 实际形态 |
|---|---|
| 浏览器 | 本机浏览器访问 `127.0.0.1` 上的本地服务 |
| 桌面端 | Electron 打包外壳，本地服务作为 sidecar |

二者的差异只有「外壳能提供哪些 OS 服务」，没有一个是「远程」。

**「服务端」默认指本机本地服务进程**，不是公有云。需要区分远端多租户时必须写明「远端实例 / 多租户云」。
